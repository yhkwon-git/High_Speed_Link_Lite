# 아키텍처

## 경계

```text
호스트 SoC
  cfg / req / rsp          디지털, 이 저장소
-----------------------
hsl_base_die_lite
  MC | PHY digital | DFT
-----------------------  핀: CK, CKE, 행 CA, 열 CA, beat {DQ, DBI, RED} + WDQS, RDQS
아날로그 PHY + DRAM 코어 다이
```

이 경계는 custom HBM 구조를 전제로 한다. 표준 HBM(HBM3E까지)이라면 컨트롤러와 PHY 트레이닝 로직은 호스트 SoC에 있고, base die의 경계는 호스트가 보낸 행 · 열 명령을 받는 핀에서 시작한다. custom HBM은 로직 공정으로 만든 base die에 컨트롤러를 옮기고, 그 뒤에 core die로 가는 TSV PHY를 둔다. 이 저장소의 핀은 그 TSV 쪽 경계 자리에 공개된 HBM 인터페이스 개념을 축소해 둔 것이다.

메모리 컨트롤러는 뱅크와 버스트를 안다. PHY는 핀의 UI와 스트로브를 안다. 이 분리는 DFI에서 가져온 발상이고, 포트 정의는 DFI가 아니다. 둘 사이는 DFI 형태의 신호다: 행 명령(cmd, bank, row)과 열 명령(cmd, bank, col, auto-precharge)이 매 클럭, 쓰기 데이터는 WR 뒤 WL 클럭에 `wrdata_en`과 함께, 읽기 데이터는 `rddata_valid`와 함께 돌아온다.

## 선택지

세 가지를 비교하고 A를 v0.1로 골랐다.

| | A. 단일 클럭, 버스트 폭 | B. 컨트롤러 1 : PHY 2 | C. RTL에서 UI 직렬화 |
| --- | --- | --- | --- |
| 성능 스터디 | 뱅크 타이밍과 스케줄 효율 | A에 더해 기어박스 처리량 | 파형으로 eye를 보기 좋음 |
| 전력 스터디 | DBI, CKE, OE | A와 같고 클럭이 하나 더 있음 | 토글이 핀 단위라 DBI 효과가 잘 보임 |
| 면적 | 32비트 데이터패스 | 20비트 PHY beat(2 UI × 10핀)와 작은 FIFO | 시프트 레지스터는 작지만 검증 시간이 김 |
| 리스크 | CDC를 아직 배우지 못함 | 포인터 동기화 버그 | 시뮬이 느리고 아날로그처럼 보이기 쉬움 |

v0.1은 A로 시작했다. 명령이 드롭되지 않는 핸드셰이크와 뱅크 타이밍을 먼저 닫기 위해서다. E7에서 시뮬과 SDC를 B의 2:1로 옮겼다. `clk_phy`는 `hsl_phy_clk`가 만들고, mission 데이터패스(`6a5a4ce`)에서 TX 기어와 RDQS 읽기 FIFO가 칩 경로에 들어왔다. 처음의 저속 bypass 프레이머는 컨트롤러 교체(`0193c04`)와 함께 없앴다.

C는 채택하지 않는다. 핀의 UI 직렬화는 아날로그 PHY 경계 밖에 둔다.

같은 경계가 지연선에도 적용된다. 디지털은 레인마다 코드(`rx_dly_code`)를 정하고, 지연선과 샘플러는 아날로그다. 읽기 레벨링은 그 코드를 스윕해 레인별 통과 구간을 찾는 디지털 알고리즘이다.

## 목표 클럭과 시뮬 클럭

의도는 다음 식이다.

```text
CK = 3.2 Gb/s / 2 = 1.6 GHz
beats_per_burst = BL / DDR_BITS = 2
컨트롤러 클럭 = CK / 2 = 800 MHz
```

한 컨트롤러 클럭에 버스트 하나(32비트)가 실린다. PHY beat는 2 UI × 10핀(DQ 8, DBI, RED) = 20비트다.

E7 이후 시뮬레이션과 SDC는 이 식과 같다. 컨트롤러 반주기는 625 ps, PHY 반주기는 312.5 ps다. 패키지 상수, 테스트벤치, `hsl_phy_clk`, SDC의 대조는 `docs/e12_clocks.md`다. 이 숫자를 JEDEC 핀 속도로 말하지 않는다.

칩 STA(`14fec6e`, Nangate45 typical, 이상 클럭)에서 HSL 로직은 800 MHz, 1.6 GHz, RDQS를 모두 통과한다. 컨트롤러는 2.18 ns(459 MHz)에서 닫힌다(`8af801b`에서는 2.14 ns, 같은 RTL의 ABC 실행 간 차이). 한 클럭에 명령을 고르고 모든 타이머를 갱신하는 루프가 그 경로다. 이 라이브러리에서 800 MHz 명령률을 지키려면 DFI 1 : 2(컨트롤러 400 MHz, 클럭마다 명령 슬롯 두 개)가 맞는 방향이다. 자세한 경로와 선택지는 README의 STA 절과 `docs/05_pd_guide.md`에 있다.

## 메모리 컨트롤러

컨트롤러는 Mini DRAM Controller v4 RTL(`rtl/mc/`)을 파일 그대로 쓴다. 읽기 8 · 쓰기 8 큐에서 FR-FCFS로 고르고(열린 row에 맞는 요청 먼저, 같으면 오래된 것), 행 명령과 열 명령을 매 클럭 하나씩 낸다. 쓰기는 받은 즉시 응답하고 쓰기 배치(WR_HI 6 / WR_LO 2)로 모아 내며, 쓰기 큐에 있는 주소의 읽기는 큐에서 답한다. refresh는 per-bank(REFpb)로 tREFI/4마다 한 뱅크씩 내고, 뱅크마다 ACT를 세어 RFM을 낸다. 컨트롤러 단독 검증과 구조 비교(큐 깊이, 명령 버스 수, refresh 방식, 주소 맵)는 그 저장소에 있다.

처음에는 in-order 컨트롤러(큐 head만 발행, 뱅크 FSM ×4)로 시작했다. mission 데이터패스를 붙이고 재 보니 PHY는 매 클럭 명령을 받는데 컨트롤러가 같은 뱅크의 컬럼 명령 사이에도 tWR · tRTP를 기다려, 한 row에 WR 16 → RD 16이 162 클럭 걸렸다. 같은 트래픽이 v4로 77 클럭이었고(`8af801b`), ECC의 읽기 단계를 더한 뒤 81 클럭이다(T12).

이 저장소에서 컨트롤러 RTL은 고치지 않는다. 통합에 필요했던 두 가지(ModelSim 10.1d가 읽지 못하는 파라미터 폭 캐스트, 레인 BIST가 기다릴 `q_empty` 출력)는 그 저장소에서 고치고 회귀를 다시 돌린 뒤(`44a0bb3`) 가져왔다.

PHY 쪽 경계에서 정한 것:

- 명령은 한 클럭 레지스터만 거쳐 핀으로 간다. 코드도 `dram_cmd_e` 그대로다. 그래서 핀에서 잰 명령 간격이 컨트롤러가 지킨 간격과 같다(T2).
- 쓰기 데이터는 WR이 핀에 나온 뒤 1.5 클럭에 첫 beat가 나간다. 같은 주소의 RD는 컨트롤러가 tWTR_L(4)을 지키므로 데이터보다 먼저 닿지 않는다. 채널 모델이 이를 검사한다.
- 읽기 지연은 고정하지 않는다. 컨트롤러는 진행 중인 RD를 `rddata_valid`로 세고(최대 4개) 순서만 맞춘다. 이 PHY에서 RD 하나는 낸 클럭부터 data_valid를 받을 때까지 8 클럭 슬롯을 잡아, 읽기만으로는 데이터 버스의 절반까지 쓴다. 컨트롤러 저장소의 모델은 3 클럭이라 이 제약이 보이지 않았다.

## 데이터 배치

버스트는 beat-major다.

```text
beat b = data[b*DQ_W +: DQ_W]
beat 안의 bit i = DQi
```

DBI와 ECC는 한 UI의 바이트를 한 덩어리로 본다. 레인 단위로 저장하면 이 연산이 비트를 흩어 읽는다. TX 기어는 버스트를 beat 두 개로 잘라 낸다.

## 리셋

- 핀 `rst_n`은 비동기 assert, `hsl_rst_sync`가 2플롭으로 deassert를 맞춘다.
- CSR은 동기화된 리셋만 본다.
- `soft_rst`는 CSR 바깥의 데이터패스만 리셋한다. CSR까지 리셋하면 비트가 스스로 지워져 리셋을 유지할 수 없다.

## 핸드셰이크 규칙

`valid && ready`일 때만 요청과 응답이 넘어간다. `ready`가 0인데 `valid`를 무시하면 실패다. `req_ready`는 MISSION이면서 `phy_en`이고 컨트롤러가 받을 수 있을 때 1이다. 컨트롤러는 큐가 찼을 때, 진행 중인 요청이 15개(tag)일 때, 쓰기 주소가 읽기 큐에 있을 때 0을 낸다. 호스트가 `rsp_ready`를 내리면 응답이 쌓여 tag가 차고 결국 `req_ready`가 0이 된다(SMOKE). 레인 BIST나 MBIST가 도는 동안 호스트의 `req_ready`와 `rsp_valid`는 0이다.
