# 아키텍처

## 경계

```text
호스트 SoC
  cfg / cmd / rsp          디지털, 이 저장소
-----------------------
hsl_base_die_lite
  MC | PHY digital | DFT
-----------------------  핀: CK, CKE, CA, DQ, DBI, RED, DQS
아날로그 PHY + DRAM 코어 다이
```

메모리 컨트롤러는 뱅크와 버스트를 안다. PHY는 핀의 UI와 스트로브를 안다. 이 분리는 DFI에서 가져온 발상이고, 포트 정의는 DFI가 아니다.

## 선택지

세 가지를 비교하고 A를 v0.1로 골랐다.

| | A. 단일 클럭, 버스트 폭 | B. 컨트롤러 1 : PHY 2 | C. RTL에서 UI 직렬화 |
| --- | --- | --- | --- |
| 성능 스터디 | 뱅크 타이밍과 스케줄 효율 | A에 더해 기어박스 처리량 | 파형으로 eye를 보기 좋음 |
| 전력 스터디 | DBI, CKE, OE | A와 같고 클럭이 하나 더 있음 | 토글이 핀 단위라 DBI 효과가 잘 보임 |
| 면적 | 32비트 데이터패스 | 16비트 PHY beat와 작은 FIFO | 시프트 레지스터는 작지만 검증 시간이 김 |
| 리스크 | CDC를 아직 배우지 못함 | 포인터 동기화 버그 | 시뮬이 느리고 아날로그처럼 보이기 쉬움 |

v0.1은 A로 시작했다. 명령이 드롭되지 않는 핸드셰이크와 뱅크 타이밍을 먼저 닫기 위해서다. E7에서 시뮬과 SDC를 B의 2:1로 옮겼다. `clk_phy`는 `hsl_phy_clk`가 만들고, 기어박스와 비동기 FIFO는 그 클럭에 있다. 채널 모델과 주고받는 bypass 프레이머는 여전히 컨트롤러 클럭에서 버스트를 한 박자씩 낸다.

C는 채택하지 않는다. 핀의 UI 직렬화는 아날로그 PHY 경계 밖에 둔다.

## 목표 클럭과 시뮬 클럭

의도는 다음 식이다.

```text
CK = 3.2 Gb/s / 2 = 1.6 GHz
beats_per_burst = BL / DDR_BITS = 2
컨트롤러 클럭 = CK / 2 = 800 MHz
```

한 컨트롤러 클럭에 버스트 하나(32비트)가 실린다. PHY beat는 16비트다.

E7 이후 시뮬레이션과 SDC는 이 식과 같다. 컨트롤러 반주기는 625 ps, PHY 반주기는 312.5 ps다. 패키지 상수, 테스트벤치, `hsl_phy_clk`, SDC의 대조는 `docs/e12_clocks.md`다. 이 숫자를 JEDEC 핀 속도로 말하지 않는다.

## 스케줄러

기본은 in-order다. 스케줄러는 큐의 head만 발행한다. head의 뱅크가 막혀 있고 다른 뱅크가 열려 있어도 뒤의 명령을 빼지 않는다.

대역은 손해를 본다. 검증과 면적은 단순하다. 뱅크 FSM을 스케줄러 밖에 둔 이유는, 나중에 head가 아닌 엔트리를 고르는 단계로 바꿀 때 큐 저장 구조를 다시 짜지 않기 위해서다.

## 데이터 배치

버스트는 beat-major다.

```text
beat b = data[b*DQ_W +: DQ_W]
beat 안의 bit i = DQi
```

DBI와 ECC는 한 UI의 바이트를 한 덩어리로 본다. 레인 단위로 저장하면 이 연산이 비트를 흩어 읽는다. 기어박스는 beat를 잘라 PHY로 넘긴다.

## 리셋

- 핀 `rst_n`은 비동기 assert, `hsl_rst_sync`가 2플롭으로 deassert를 맞춘다.
- CSR은 동기화된 리셋만 본다.
- `soft_rst`는 CSR 바깥의 데이터패스만 리셋한다. CSR까지 리셋하면 비트가 스스로 지워져 리셋을 유지할 수 없다.

## 핸드셰이크 규칙

`valid && ready`일 때만 비트가 이동한다. `ready`가 0인데 `valid`를 무시하면 실패다. `cmd_ready`는 `mission_mode`이고 큐에 빈 슬롯이 있을 때 1이다. 리셋 직후와 깊이 4가 가득 찼을 때는 0이다. `phy_bypass`가 0이면 TX ready도 0이라, 스케줄러가 기어박스 쪽으로 명령을 넘기지 않는다.
